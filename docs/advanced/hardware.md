# 硬件与内存层次

并发程序的性能与正确性最终落在硬件上：缓存一致性决定多核之间「看到什么」，内存层次决定「等多久」，NUMA 与 I/O 决定「数据从哪来」。本页讲硬件侧的成因，语言侧的规则见[内存模型](./memory-model.md)，软件侧的调优见[性能调优](./performance.md)。

## 内存层次与延迟阶梯

| 层级 | 典型容量 | 典型延迟（周期） | 归属 |
|------|---------|----------------|------|
| 寄存器 | 百字节级 | 0–1 | 单核 |
| L1 缓存 | 32–64 KB | ~4 | 单核私有 |
| L2 缓存 | 256 KB–2 MB | ~12 | 单核私有 |
| L3 缓存 | 数 MB–数十 MB | ~40 | 多核共享 |
| 主存（DRAM） | GB 级 | ~200 | 全机共享 |
| NVMe SSD | TB 级 | 数万 | 全机共享 |
| 网络/磁盘 | — | 数十万以上 | 跨机 |

数量级记忆法：主存比 L1 慢约两个数量级，SSD 再慢两个数量级。并发的价值正是把这些等待重叠起来（见[并发基础概念](../basics/concepts.md)），而缓存一致性协议决定多核重叠时的代价。

**缓存行（cache line）**是搬运的最小单位，x86 与 ARM 常见为 64 字节。两个无关变量落在同一行，一个核写、另一个核读，协议会判定为冲突——这就是[伪共享](./data-structures.md)的硬件成因，软件侧用 padding 与 `@Contended` 拆行，硬件侧无法避免。

## 缓存一致性协议：MESI 与它的变体

多核各自有缓存，同一地址的副本必须保持一致。主流协议是**写失效（write-invalidate）**路线的 MESI，每个缓存行的四个状态：

| 状态 | 含义 | 本核可读 | 本核可写 |
|------|------|---------|---------|
| **M** Modified | 已修改，仅本核持有，与主存不一致 | 是 | 是 |
| **E** Exclusive | 独占，未修改，与主存一致 | 是 | 是（转 M） |
| **S** Shared | 共享，多核持有，均未修改 | 是 | 否（需先失效他人副本） |
| **I** Invalid | 无效 | 否 | 否 |

写一个处于 S 的行，本核要先广播失效请求、等其他核确认，才能进入 M——**这就是写共享数据比写私有数据慢的原因**，也是无锁编程里 CAS 竞争激烈时吞吐骤降的硬件层解释。

变体 MOESI 增加 O（Owned）状态，把「已修改但可共享」的脏行留在持有者处，减少回写主存的次数；AMD 与部分 ARM 实现采用。总线监听（snooping）适合核数少的场景，核数一多改**目录协议（directory）**，用中心目录记录谁持有哪行，避免广播风暴。

一致性协议保证的是**单地址的最终一致**，不保证跨地址的顺序——顺序交给[内存模型](./memory-model.md)的屏障规则。

## 屏障指令与 store buffer

现代 CPU 为隐藏写延迟，把写先放进 **store buffer**，读请求则直接进缓存（store-load 不保序的来源）；失效请求也有**失效队列（invalidate queue）**，收到失效后不立即处理（store-store 与 load-load 不保序的来源）。

| 重排 | 硬件机制 | 修它的屏障 |
|------|---------|-----------|
| Store-Load | store buffer 转发 | 全屏障（mfence / DMB SY） |
| Store-Store | 写合并与缓冲 | sfence / DMB ST |
| Load-Load | 乱序执行与失效队列 | lfence / DMB LD |

- **x86/TSO**：总存储序模型，只允许 Store-Load 重排，`mfence` 与 `lock` 前缀即可，日常需要的屏障很少
- **ARM/POWER**：弱序模型，四类重排都可能发生，需要显式 `DMB/DSB/ISB`，这也是 ARM 上并发 bug 更易暴露的原因

语言里的 `memory_order_acquire/release`、`volatile`、`std::atomic` 最终编译成这些指令；把语言规则与硬件指令对照读，才知道每行代码付了多少代价（[C++ 书把内存序放在无锁设计之前讲](../research/books.md)正是这个道理）。

## NUMA：内存不再等距

多路服务器上每个 CPU 有自己的本地内存控制器，访问本地内存比跨节点快（典型差异在 1.5–2 倍量级）。两个后果：

- **线程亲和性**：线程绑到核心、内存绑到本地节点，跨节点访问的隐性开销才可控（Linux 下 `numactl`、`taskset`）
- **首次触碰（first touch）**：页分配给第一个写它的线程所在的节点，初始化阶段单线程跑完，后续多线程全在跨节点访问——大数组初始化要并行化

NUMA 失配的表现是「核加了、吞吐没涨」，排查先看 `numastat` 的远端命中率。

## 存储与 I/O

- **DMA**：外设直接读写主存，CPU 不参与搬运，只处理完成通知；零拷贝（sendfile、mmap）进一步省掉用户态与内核态的来回
- **页缓存**：读走缓存、写回写盘，`fsync` 才保证落盘——持久化语义的边界在这里，不在语言层
- **高并发 I/O 多路复用**：epoll（Linux）、kqueue（BSD/macOS）、io_uring（Linux 5.1+ 的异步提交/完成环）把「等 I/O」从线程切换里拿出来，是 Netty、asyncio、Go runtime netpoller 的共同底座，上层结构见 [Reactor 模式与事件驱动](../practice/reactor.md)
- **SSD 与队列深度**：NVMe 支持高并发队列，单盘吞吐靠队列深度堆出来；并发度不够时延迟不降反升

I/O 侧的关键认知：**CPU 与内存之间的一切优化，都可能在一次未命中的 I/O 前失效**，所以高并发系统的第一层设计往往是「别让请求等 I/O」。

## 加速器在高并发中的位置

| 加速器 | 并行形态 | 适用 |
|--------|---------|------|
| SIMD（AVX/NEON） | 单指令多数据，宽 128–512 位 | 向量化的规则计算，编译期/运行期自动或手写 |
| GPU | SIMT，数千轻量线程 | 计算密集、规则数据（见[数据并行](../models/data-parallel.md)） |
| FPGA | 硬件电路级流水线 | 固定算法、超低延迟（网络包处理、行情解析） |
| DPU/SmartNIC | 网卡上卸载 | 网络与存储协议栈卸载 |

选型判断：并行度天然高、分支稀少、数据量大，才值得把计算搬到加速器；否则数据搬运的成本会超过收益（[数据并行的传输陷阱](../models/data-parallel.md)同源）。

## 本章小结

硬件层的三句话：**缓存一致性让多核共享内存成为可能，代价是写共享数据要付失效成本**；**store buffer 与失效队列带来重排，屏障指令与语言内存序是给它们的约束**；**内存层次与 NUMA 决定延迟量级，并发的收益上限由它们划定**。软件侧的一切并发手段——锁、原子、无锁、分片、亲和性——都是在这三条约束下的工程解。
