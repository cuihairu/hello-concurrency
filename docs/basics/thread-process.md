# 线程与进程

进程是操作系统资源分配的基本单位，线程是 CPU 调度的基本单位。理解二者关系是并发编程的起点。

## 进程

进程拥有独立的地址空间，包含代码段、数据段、堆、栈等资源。进程间隔离性强，但创建、切换开销大。

### 进程特征
- **独立性**：拥有完整的虚拟地址空间，互不干扰
- **动态性**：进程是程序的一次执行过程，有生命周期
- **并发性**：多进程可在宏观上并行执行
- **结构性**：由程序、数据、PCB 组成

### 进程状态
```
就绪 → 运行 → 阻塞
 ↑          ↓
 └──────────┘
```

## 线程

线程是进程内的一个执行流，共享进程的地址空间和资源，仅拥有私有的栈、寄存器、程序计数器。

### 线程优势
- **轻量**：创建、销毁、切换开销远小于进程
- **共享**：天然共享进程内存，通信高效
- **响应**：单进程多线程可并发处理多个请求

### 线程模型
| 模型 | 特点 | 典型实现 |
|------|------|----------|
| 用户级线程 | 内核不感知，切换快，阻塞影响整个进程 | Green threads |
| 内核级线程 | 内核调度，阻塞不影响其他线程，切换开销大 | pthreads, Windows threads |
| 两级模型 | 结合两者优点，用户线程映射到内核线程 | Go goroutines, Java 虚拟线程 |

## 线程 vs 进程对比

| 维度 | 进程 | 线程 |
|------|------|------|
| 地址空间 | 独立 | 共享 |
| 创建开销 | 大（复制页表、文件描述符等） | 小（仅分配栈、寄存器） |
| 切换开销 | 大（TLB 刷新、上下文切换） | 小（保存/恢复寄存器、栈指针） |
| 通信方式 | IPC（管道、Socket、共享内存） | 共享内存、锁、条件变量 |
| 稳定性 | 崩溃不影响其他进程 | 一个线程崩溃导致整进程退出 |
| 并行能力 | 受限于进程数 | 单进程内可高并发 |

## 线程生命周期

```
新建 → 就绪 → 运行 → 阻塞 → 终止
           ↑        ↓
           └────────┘
```

## 上下文切换

线程切换涉及：保存当前线程寄存器、程序计数器、栈指针 → 恢复目标线程上下文 → 流水线作废重填。线程共享地址空间，切换**不刷 TLB**（页表项仍然有效）；刷 TLB 是**进程**切换的事——切换地址空间后才需要（PCID/ASID 可进一步摊薄这部分开销）。频繁切换会严重影响性能。谁来决定切换、被动抢占的成本从哪来，见[操作系统与并发](../advanced/os.md)的调度一节。

## 最佳实践

1. **IO 密集型**：多线程显著提升吞吐，线程数可配置为 2×CPU 核心数
2. **CPU 密集型**：线程数约等于 CPU 核心数，避免过度切换
3. **避免线程泄漏**：使用线程池管理生命周期
4. **线程局部存储**：ThreadLocal 存放线程私有数据，避免同步开销
