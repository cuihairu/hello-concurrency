# 临界区与互斥

临界区是访问共享资源的代码段，互斥机制保证同一时刻仅有一个线程进入临界区，是并发编程的基石。

## 临界区问题

### 定义
多个线程并发访问共享资源（变量、文件、设备等）时，若不加控制，最终结果取决于执行时序，这就是临界区问题。

### 经典示例：银行账户转账
```java
// 非线程安全
class Account {
    private int balance = 1000;
    void transfer(int amount) {
        balance = balance - amount;  // 非原子操作：读-改-写
    }
}
```
两个线程同时转账 100 元，预期余额 800，实际可能 900（丢失更新）。

### 临界区三要素
1. **共享资源**：被多线程访问的数据或设备
2. **临界区代码**：访问共享资源的代码段
3. **互斥机制**：保证同一时刻仅一个线程进入临界区

## 互斥的实现层级

### 硬件层：原子指令
- **Test-and-Set (TSL)**：原子读取并写入
- **Compare-and-Swap (CAS)**：比较并交换，现代 CPU 核心原语
- **Load-Linked/Store-Conditional (LL/SC)**：ARM、RISC-V 常用

### 操作系统层：系统调用
- **Mutex / 互斥锁**：阻塞式互斥，拥有权概念
- **Spinlock / 自旋锁**：忙等待，适合极短临界区
- **Semaphore / 信号量**：计数器机制，可实现互斥与同步

### 语言/库层：高级抽象
- `synchronized` (Java)、`lock` (C#)、`std::mutex` (C++)
- `threading.Lock` (Python)、`sync.Mutex` (Go)
- `ReentrantLock`、读写锁、StampedLock 等进阶锁

## 互斥锁的核心特性

| 特性 | 说明 |
|------|------|
| **互斥性** | 同一时刻仅一个线程持有锁 |
| **可见性** | 解锁前的写入对加锁后的线程可见 |
| **重入性** | 同一线程可重复获取同一把锁（递归锁） |
| **公平性** | 等待队列按请求顺序获取锁（公平锁） |

## 锁的分类与选型

### 按实现分
| 类型 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| 自旋锁 | 临界区极短、无阻塞操作 | 无上下文切换开销 | 占用 CPU、长临界区灾难 |
| 互斥锁 | 通用场景、可能阻塞 | 线程睡眠不占 CPU | 切换开销大 |
| 读写锁 | 读多写少 | 读并发、写独占 | 写饥饿、实现复杂 |
| 递归锁 | 递归调用同一临界区 | 简化递归逻辑 | 易掩盖设计缺陷 |

### 按公平性分
- **公平锁**：按请求顺序获取，吞吐较低，无饥饿
- **非公平锁**：抢占式，吞吐高，可能饥饿（默认选择）

## 锁粒度权衡

| 粒度 | 并发度 | 开销 | 复杂度 | 典型场景 |
|------|--------|------|--------|----------|
| 粗粒度（全局锁） | 低 | 低 | 低 | 简单业务、低并发 |
| 细粒度（分段锁、分桶锁） | 高 | 高 | 高 | 高并发容器、数据库 |
| 无锁（CAS、原子变量） | 极高 | 中 | 极高 | 计数器、队列、引用 |

## 常见错误模式

1. **双重检查锁定失效**：指令重排导致对象未完全初始化就被可见
2. **锁对象变化**：`synchronized(list)` 后 `list = new ArrayList()`
3. **锁过大**：临界区包含 I/O、睡眠、日志等耗时操作
4. **忘记解锁**：异常路径未释放，必须用 `try-finally` 或 `defer`
5. **嵌套锁顺序不一致**：导致死锁

## 无锁替代方案

- **ThreadLocal**：线程私有副本，避免共享
- **不可变对象**：天然线程安全，无需加锁
- **原子类**：`AtomicInteger`、`LongAdder` 等
- **并发容器**：`ConcurrentHashMap`、`CopyOnWriteArrayList`
- **Actor/CSP 模型**：通过消息传递避免共享状态
