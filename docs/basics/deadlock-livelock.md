# 死锁与活锁

死锁与活锁是并发编程中最棘手的病理现象，理解其成因、检测与预防是构建鲁棒并发系统的关键。

## 死锁

### 定义
两个或多个线程因互相等待对方持有的资源而永久阻塞，系统无法推进。

### 死锁四必要条件（Coffman 条件）
1. **互斥条件**：资源独占使用
2. **请求与保持**：持有资源时请求新资源
3. **不可剥夺**：资源只能主动释放
4. **循环等待**：形成环路等待链

**四条件同时成立 ⇔ 死锁发生**，破坏任一条件即可预防死锁。

### 经典死锁示例
```java
// 哲学家进餐问题：5 位哲学家共享 5 支筷子
// 每位哲学家需要左右两支筷子才能进餐
// 全部拿起左筷 → 全部等待右筷 → 死锁
```

### 死锁预防策略

| 策略 | 破坏条件 | 实现方式 | 代价 |
|------|----------|----------|------|
| 资源一次性申请 | 请求与保持 | 启动时申请所有资源 | 资源利用率低、饥饿 |
| 资源有序分配法 | 循环等待 | 全局编号，按序申请 | 编程约束、灵活性差 |
| 允许资源抢占 | 不可剥夺 | 超时释放、优先级抢占 | 实现复杂、可能饿死 |
| 超时机制 | 循环等待 | `lock.tryLock(timeout)` | 需业务可重试 |

### 死锁避免：银行家算法
运行时动态判断资源分配是否安全，仅用于资源类型固定、进程已知的场景，工程实践较少用。

### 死锁检测与恢复
- **检测**：资源分配图 / 等待图找环
- **恢复**：终止进程、资源抢占、回滚

### 工程实践：死锁排查清单
1. **固定加锁顺序**：全局规约，代码审查强制执行
2. **避免嵌套锁**：单锁设计，必要时用 `tryLock` + 回退
3. **锁超时**：所有阻塞锁改为带超时版本
4. **死锁监控**：jstack / `go tool pprof` 定期巡检
5. **锁分级**：按业务层级编号，高层不调用低层锁

## 活锁

### 定义
线程非阻塞但持续重试、让步，始终无法推进。类比：两人过走廊反复礼让，谁也过不去。

### 典型场景
```java
// 经典活锁：双方同时检测冲突、同时后退、同时重试
while (!tryAcquire()) {
    backoff();  // 固定退避 → 同步重试 → 永久冲突
}
```

### 活锁 vs 死锁对比

| 特征 | 死锁 | 活锁 |
|------|------|------|
| 线程状态 | 阻塞 | 运行（但无进展） |
| CPU 占用 | 低 | 高（忙等待） |
| 根因 | 资源循环等待 | 重试策略同步 |
| 解法 | 破坏四条件 | 随机退避、队列化 |

### 活锁预防
- **随机退避**：`ThreadLocalRandom.current().nextInt(100)` 打破同步
- **指数退避**：失败次数越多，等待越久
- **队列化**：将竞争转为排队，如 `ReentrantLock` 公平模式
- **避免对称逻辑**：引入随机性或优先级区分

## 饥饿

### 定义
线程长期无法获得 CPU 时间片或所需资源，导致任务无法推进。

### 常见原因
- **优先级反转**：高优先级等待低优先级持有的锁
- **非公平锁**：新来线程持续抢占，老线程饥饿
- **资源耗尽**：连接池、线程池耗尽无新资源

### 解决方案
- **优先级继承/天花板**：临时提升持锁线程优先级
- **公平锁 / 等待队列**：保证先来先服务
- **资源配额**：限流、分级隔离
- **监控告警**：队列积压、等待时长指标

## 优先级反转与优先级继承

### 场景
```
高优先级 H 等待锁 L
中优先级 M 抢占 CPU
低优先级 L 持有锁但无法运行 → H 永久等待
```

### 优先级继承协议
L 持有锁期间，临时继承 H 的优先级，抢占 M 运行，释放锁后恢复。

### 实现支持
- pthread: `pthread_mutexattr_setprotocol(PTHREAD_PRIO_INHERIT)`
- FreeRTOS: `configUSE_PRIORITY_INHERITANCE`
- Linux futex: `FUTEX_LOCK_PI`

## 本章小结

| 现象 | 核心成因 | 核心对策 |
|------|----------|----------|
| 死锁 | 循环等待 | 固定锁序、超时、避免嵌套 |
| 活锁 | 同步重试 | 随机退避、队列化 |
| 饥饿 | 调度不公 | 公平锁、优先级继承、配额 |

死锁预防胜于检测，检测胜于恢复。工程上**固定加锁顺序 + 带超时锁 + 死锁监控**是性价比最高的组合拳。
